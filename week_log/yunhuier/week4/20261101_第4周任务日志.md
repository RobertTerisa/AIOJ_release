### 1.3 参数与行为

| 参数 | 必填 | 说明 |
|---|---|---|
| `--seed` | 是 | 决定输出；同一 seed 必须逐字节一致 |
| `--out` | 是 | 输出文件路径 |
| `--append` | 否 | 路由总是传入；只追加 content，不写控制头 |
| `--array 长度,最小值,最大值` | 至少一个 | 可重复；每个输出一行，恰好“长度”个整数，数值按 64 位处理 |

行为约定（均按 Readme 第 5 节实现）：

- 只写 content 值，**不写 `T`、不写 `n`、不写控制头、不写 JSON**；
- 每行行内单空格分隔、行末 LF、**文件末尾有换行**；二进制方式打开文件，杜绝 CRLF；
- 禁用 `time()` / `random_device()`，同一 seed 输出完全可复现；
- 任何参数问题一律非 0 退出并把原因写 stderr，不写半截文件；
- 区间放不下严格单调序列时（跨度 < n−1）直接报错，不静默产出越界数据。

## 2. 本周总结

1. CLI 化的关键不是“加几个参数”，而是**把控制权从源码移到调用方**：`--array` 天然支持多个数组、每个数组独立区间，这正好覆盖了“一个 spec 里可能有多组约束”的情况，比写死单个 N 灵活得多。
2. `common.h` 的 `parse_common` 对缺失 `--seed` **不报错**（默认 0），但 Readme 要求缺失即非 0 退出。因此 main 里在 `parse_common` 之前先自己扫一遍 `argv` 检查 `--seed` 是否存在——这是一个“文档要求严于工具库行为”的坑，值得写进这里留给后面的人。
3. 区间可行性检查必须在生成之前做：跨度 < n−1 时无解；有了它，“步长上限动态收缩”才有可能始终 `cap ≥ 1`，否则 `uniform_int_distribution(1, 0)` 是未定义行为。
4. 严格单调的两个方向要对称地留空间：递增给起点留出上限空间，递减给起点留出下限空间；把这一点写成注释，比事后解释省事。
5. 关于“代码必须手写”：本次两个生成器由 AI 起草，本人逐行核对并理解了关键实现——`--array` 的解析与校验顺序、步长动态收缩为什么不会越界、为何必须二进制打开文件，以及 `--seed` 预检查为何不能省；**未按任务单“手写”要求执行，如实记录**。
